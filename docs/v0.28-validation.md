# Validation of the 0.28.0 port (PR #43 head 06b3185 + one build repair), 2026-09-03

Image built from this branch (`v0.28-validation`), RTX 4090 under WSL2 (24 GB, `GPU_UTIL=0.93`), the launchers as
shipped on this branch, `PREFIX_CACHE=1`, compile cache disabled on every boot. A second machine (native RTX 3090,
Ubuntu) runs the same cells; its rows are cited by commit when they land. Everything here is one boot per cell.

KV need (4.76 GiB) exceeds this WSL2 card's budget at 0.93 (4.71 GiB); the native 3090 boots the default.

Reading, so far: every cell boots, including the KVarN cells the reshape crash used to kill; the count probe passes
everywhere, which is expected to be too easy for the KVarN + DFlash2 cell (the maintainer saw degradation at depth
7 on a longer answer and token soup at depth 15; the ladder below uses four longer probes). Two warnings are new
against 0.27.1 and need the capture-mode story re-proven rather than assumed: the int8 tier logs that full CUDA
graphs are unsupported with speculative decoding for its attention backend, and the DFlash2 cells report up to 60%
KV padding waste against 6.25% under MTP. For comparison, 0.27.1 current main with the same int4 settings pools
252,573 tokens at `MAX_LEN=244224` on this card; the 0.28 port with the connector attached pooled 256,892.
