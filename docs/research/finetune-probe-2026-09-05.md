## Ten-line summary (as delivered)

1. Yes. SpecForge's DFlash2 trainer ran optimizer steps on this box's RTX 4090 (host GPU 1), warm-started from the shipped W4A16 head (dequantized to bf16, 81/81 tensors, 1,924,404,480 params), against hidden states captured from the W4A16 target in vLLM.
2. Warm-start sanity check passed: on the first batch the untouched head scored position-1 top-1 accuracy 0.644 and selector serving accepted length 3.20, in line with the repo's measured acceptance, so the layer convention (target id i = output of 0-indexed layer i, which SpecForge and vLLM share) and the dequantization are right.
3. The recipe's 512 anchors do not fit 24 GiB: those runs took 115 to 129 s per step because under WSL2 CUDA allocations silently spill into host RAM instead of raising OOM (the optimizer benchmark reported a 43 GiB peak on a 24 GiB card).
4. At 256 anchors the same steps take 6.3 to 7.6 s (peak 23.3 GiB as seen by nvidia-smi); at 128 anchors 6.5 to 7.1 s (20.6 GiB). The floor is the CPU-offloaded AdamW step, 6.5 s per optimizer step for 1.92B params.
5. With gradient accumulation 8 the amortized cost is 1.26 s per sample (10.05 s per optimizer step over 8 samples of about 617 tokens); forward+backward is about 0.45 s per sample.
6. Estimate for a 50k-sample warm-start epoch on one 4090: about 17.5 h of training (9 h at accumulation 32) plus 15 to 25 h of on-policy generation and capture, so 33 to 43 GPU-hours; each extra epoch adds 9 to 18 h. Hidden states are 30.8 MB per sample (1.5 TB for 50k), so capture must be chunked and rotated.
7. Three environment failures had to be cleared, none in SpecForge itself: expandable_segments:True breaks Marlin repack under WSL2 (the repo's launcher documents this), flashinfer's JIT top-k in the DFlash2 speculator needed ninja on PATH, and Docker's --gpus device=1 is not honoured on this host (the container saw both cards; pinned by UUID).
8. Two SpecForge quirks matter for a real run: under the single-rank DDP path the trainer reads the selector weight off the DDP wrapper and gets 0, so the selector term was silently off in every probe step; and its flex-attention wrapper compiles with dynamic shapes off, which invites per-shape recompiles (measured below the ceiling only with sdpa).
9. Every run also wrote a 26 GB end-of-run checkpoint (fp32 masters and Adam moments included) even with save_interval: 0, taking about 2.5 min over the 9P mount.
10. Riskiest remaining unknown: the round trip back to serving. Nothing here exported a trained head, loaded it in the fork's vLLM, or measured acceptance, and the rwmacy card's position-offset trap sits exactly on that path.

## Part 3 of 6: what the trainer needs, and the dequantization (as delivered)

SECTION 2. WHAT THE TRAINER NEEDS.
- DFlash2 is a draft architecture under training.strategy: dflash (docs/concepts/DFlash2.md). Our head's config.json equals the checked-in configs/qwen3.6-27b-dflash2.json except target_layer_ids [5,19,33,47,61] and sliding_window 2048; SpecForge loads it as-is.
- Offline record contract (specforge/algorithms/common/hidden_states_data.py, runtime/data_plane/offline_reader.py, feature_store.py): one torch.save dict per sample: input_ids int64[seq], loss_mask int64[seq], hidden_states bf16[seq, 5*5120]; any directory tree of *.ckpt files (the agent used rows_0-2000/data_N.ckpt like scripts/prepare_hidden_states.py). Files are read with torch.load(mmap=True); that worked from the 9P-mounted scratch dir.
- Layer semantics: SpecForge's reference extract_context_feature in modeling/draft/dflash.py uses hidden_states[layer_id + 1]; vLLM's gpu_model_runner._get_eagle3_aux_layers_from_config adds 1 ("Add 1 to convert DFlash's aux layer id semantics") and interfaces.py:_maybe_add_hidden_state appends hidden_states + residual after layer idx under index idx+1. So target id i = the output of 0-indexed decoder layer i, the full residual stream. Both agree.
- Besides the head, the trainer loads only the target's embed_tokens and lm_head (modeling/target/target_utils.py:TargetEmbeddingsAndHead, keys model.embedding_key and model.lm_head_key) by name from the target directory's safetensors. It never loads the target transformer in offline mode. Our W4A16 checkpoint stores both as int8 pack-quantized (weight_packed/weight_scale/weight_shape), so a bf16 stub directory was required.
- Warm start: model.draft_checkpoint_path goes through AutoDraftModel.from_pretrained (training/model_loading.py:warm_start_draft_model); it needs bf16 tensors under the SGLang/SpecForge names, which the shipped head already uses (layers.N.*, fc, hidden_norm, norm, candidate_selector.*, *_conv.*).
- Optimizer BF16Optimizer (specforge/optimizer.py): fp32 masters + AdamW moments, 16 bytes per param = 28.7 GiB for 1.92B params. training.optimizer_cpu_offload: true keeps them on the host (single-tensor CPU AdamW). Without it the state alone exceeds the card.
- Memory levers: objective_chunk_blocks (checkpointed chunked LM head + CE, core/chunking.py), num_anchors, fsdp_sharding: NO_SHARD (DDP path; at world size 1 the backend otherwise still wraps in FSDP).
- Single GPU: deployment.mode: local_colocated, nproc_per_node: 1; the CLI bootstraps a one-process rendezvous (cli.py:_bootstrap_single_process_env).
- SpecForge's own capture is SGLang-only (scripts/prepare_hidden_states.py -> OfflineSGLangCapture). No SGLang here, so capture came from vLLM (part 4).

SECTION 3. DEQUANTIZATION (CPU, head done 22:36:22Z, stub written 22:37:31Z). dequant.py: compressed-tensors unpack_from_int32 then q * scale broadcast over 128-column groups, symmetric, no zero point.
- head_bf16/ from Qwen3.8-27B-DFlash2-W4A16 (int4 Linear, bf16 rest): 81 tensors, 1,924,404,480 dense params (equals the research doc's independent count exactly), 3.6 GiB; config.json copied minus quantization_config.

TWO SPECFORGE QUIRKS. 1. selector_loss_alpha was logged as 0.0 on every step despite the YAML's 1.0. DFlashTrainStrategy._selector_loss_alpha reads the attribute off self.dflash_model, which under NO_SHARD is the DDP wrapper (training/backend.py wraps in DDP; build_step receives the wrapped model); getattr(DDP, "selector_loss_alpha", 0.0) returns the default. So the selector objective was silently off in every probe step (selector metrics still computed). The default FSDP path forwards attributes but adds per-block FSDP wrapping; not measured. 2. SpecForge's flex-attention wrapper (modeling/draft/flex_attention.py) compiles with dynamic=False and recompile_limit = 64, so variable-length offline samples invite a recompile per new shape. At 512 anchors flex and sdpa had the same step times (both over the ceiling); below the ceiling only sdpa was measured, so flex's real per-step cost on this data is unmeasured.
